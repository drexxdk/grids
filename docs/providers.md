# Image Provider Compatibility

## Credentials Checklist

See [.env.example](../.env.example) for blank credentials and registration links for all credentialed image-provider candidates in the roadmap, plus a separate optional sign-in section. Keyless providers are listed without unnecessary credentials. Copy it to a local `.env`; real environment files are Git-ignored, while the example remains tracked.

The example is a preparation checklist, not runtime configuration: Commons and The Met are implemented and keyless; filling in other credentials does not enable integrations. Reserved variable names can change when those integrations are built. Credentialed integrations still require terms/rights review and approved backend/gateway hosting. Never add a `VITE_` prefix to secrets: those variables are exposed in browser builds, and GitHub Pages cannot keep them private. Do not send secrets in chats, screenshots or commits.

## Metadata Caching

- TanStack Query shares an in-memory metadata cache between the sidebar and picker. Visible pages are keyed by provider, trimmed search text (bounded to the same 160 characters sent to the API), and raw starting offset. Met details are additionally keyed by object ID, so different searches do not repeatedly fetch the same valid record. Returning to a visited page, restoring a browse topic or reopening a provider reuses fresh results. Cached data is cloned for consumers; editing a preview caption cannot alter another view's cached metadata.
- Successful results remain fresh for one hour. Inactive entries are garbage-collected after two hours; an additional 500-entry target evicts the oldest inactive metadata first, never active/in-flight work. Search pages and object details share that limit. An expired result is refreshed before being returned rather than silently treated as fresh. Search ordering can still change between independently refreshed pages; this cache is not a catalog snapshot.
- Identical concurrent queries share one request. Cancelling one consumer only removes its observer; the underlying fetch aborts when no consumers remain. Errors are not automatically retried or retained as usable results. Focus and reconnect do not trigger background refetches. Fresh cached pages remain usable during quota cooldowns or offline operation; actual network requests retain existing offline errors, Retry-After handling, deadlines and rights checks.
- Pages truncated by the shared deadline carry an incomplete marker and are immediately stale; they are not treated as complete one-hour results. Invalid Met detail schemas are also immediately stale. Valid detail metadata still passes the existing public-domain, rights and host filters before becoming an image result. This caches provider metadata, not permission guarantees or live availability; source-page review remains necessary.
- Reloading or closing the app clears this cache. It does not use IndexedDB, localStorage or service-worker runtime caching, and stores no image blobs. Imported originals and saved grids retain their separate existing local persistence. Unit checks cover freshness, expiry, failure recovery, deduplication, independent cancellation, clone isolation, incomplete pages and entry bounds; mocked editor checks cover Previous/Next, repeated searches, provider reopening, sidebar/picker sharing, Met detail reuse and one-hour expiry.

## Preview Resolution

- Online cards measure their rendered width before requesting an image and respond to resizing and screen-density changes. The editor and preview selector share the existing 128-320 CSS-pixel card limits. Resolution covers all three shapes, not just the current shape, so changing portrait/landscape/square does not need another image request. At 320 CSS pixels wide, portrait needs approximately 427 pixels of image height before accounting for screen density and the source's cover crop.
- Commons selects the smallest sufficient supported thumbnail-width bucket using original dimensions and device pixel ratio. Only validated standard Commons thumbnail URLs are resized; unknown URL layouts retain the API-provided preview. Requests never ask for a thumbnail larger than the original. Failed alternate renditions fall back to the API-provided thumbnail. The API's initial `iiurlwidth=320` supplies metadata/thumbnail URLs; it does not force the card to download that initial thumbnail before its measured rendition.
- The Met supplies only small and original image URLs, without a supported arbitrary resize contract. Cards initially use the small image, inspect its decoded dimensions, and request the original only if the small image cannot cover every shape at the measured size/density. Larger previews use the existing bounded 20 MB download and 40 MP decoded-image checks, temporary object URLs and cancellation/cleanup; they are not saved to IndexedDB. Failed larger previews retain the small image. An original may be substantially larger than needed because no intermediate provider rendition is available.
- Explicit import still downloads and stores the original, not the selected preview. This preserves independent crops and exports up to 1800x2400 pixels per portrait card; saved local originals are not destructively downsampled. Preview sizing cannot create missing detail: undersized originals, failed renditions and provider limitations can still require upscaling. Rights, approved hosts, provenance and local-only persistence rules remain unchanged.
- Focused checks cover source orientations, card sizes and 1x/2x/3x densities, smallest sufficient buckets, desktop/mobile real decoded preview dimensions, resizing, no redundant initial thumbnail fetch, stable URLs across shapes, original-only explicit import, Met sufficient/undersized variants, failed-upgrade fallback, no persisted preview blobs and temporary-URL revocation.

## Wikimedia Commons

Checked November 2, 2026. Initial integration: public-domain and CC0 JPEG, PNG and WebP files only. Other licenses, SVG, animation, unclear copyright, required attribution and nonempty restrictions are excluded. API access is not a warranty of rights: users must review the linked source page, especially for privacy, personality, trademark and jurisdiction-specific restrictions.

- Keyless MediaWiki Action API, anonymous `origin=*`, one provider per request. Selecting a provider in Image source loads its first browse topic automatically; compact Space, Nature, Art, Places and History icon buttons offer one-click discovery. The placeholder-only filter textbox automatically searches 300ms after typing stops, without a submit button. Clearing the filter restores the first topic, and selecting a topic cancels a pending text filter. Each visible page tries to collect twelve unique eligible images across at most five raw batches, requesting only its remaining slots. It stops at API exhaustion, the batch cap or the shared 15-second deadline. Smaller or empty pages remain possible; Next preserves the raw continuation cursor when more results remain, without skipping eligible overflow.
- Requests omit credentials and referrers. Search text and network identity reach Commons; image requests reach its upload CDN. Local uploads are never sent. No gateway, arbitrary URL proxy, server media storage or account dependency.
- A visible page's replacement batches share a 15-second search deadline; original download timeout is 30 seconds. Deadline expiry retains fully completed batches and their continuation cursor, if any images were collected. Caller cancellation discards the search, and service/quota/malformed-response failures retain the existing error handling rather than masquerading as exhaustion. Search changes/unmount cancel and ignore stale results. HTTP 429 honors `Retry-After`, with a 60-second default. No automatic error retries. Loading, empty, offline, malformed-response, service and import failures leave Imported and the grid available.
- Original files are streamed with a 20 MB ceiling, checked raster MIME and a 40 MP metadata/decode ceiling. Source URLs use approved HTTPS hosts. These are safeguards, not representative-device memory certification. Originals and provider/entity IDs, creator, license and source links persist in IndexedDB only; settings exclude provenance and media. Reimport of an already-visible entity reuses its local asset.
- Online previews and Imported use the same LibraryImage/GridCell card renderer, current shape/caption/font/color settings and hover tools. Sidebar Import actions add library-only; mouse and touch drags download/import the original into the dropped-on cell. Cancelled drags do not import or place anything, and failed drops leave the grid unchanged. Picker cards remain selection-only and intentionally import into the captured target cell. Original files use the existing independent crop and PNG/JPEG/WebP export path. Source and rights links remain below the shared cards and persist in Imported after reload; previews do not show a separate license heading or metadata-heavy card design.
- Isolated Chromium smoke check used a page with origin `https://drexxdk.github.io`, without touching the live editor. One `earth filetype:bitmap` search returned HTTP 200; an original public-domain NASA city-lights JPEG returned HTTP 200, decoded at 4800x2400 and produced untainted PNG, JPEG and WebP canvas exports. This verifies current browser CORS from that origin, not a deployed release, every catalog file or every browser.
- Browse follow-up, November 2: current Commons responses use `thumb.wikimedia.org` for thumbnails; both that host and the earlier upload host are allowed for previews, while originals remain upload-host-only. Before replacement loading, the actual adapter returned eligible first-batch examples for Space (11), Nature/Ansel Adams landscapes (12), Art (5), Places (6) and History (7). Counts and ordering can change with the catalog. All checks used isolated contexts, not the shared saved editor.
- Mocked CI checks cover desktop/mobile initial examples, compact titled topic buttons, inset search-icon geometry, contained focus feedback, debounced filtering without submit controls, default-topic restoration on clear, pending-filter cancellation, pagination, excluded rights, safe creator HTML-to-text conversion, stale responses, malformed data, empty/quota/offline failures, download failure/recovery, explicit import/placement, crop, actual PNG download, provenance/blob persistence and reload, plus settings exclusion. Shared-card checks compare Online and Imported across all three shapes and four caption positions with edited typography/colors, real mouse drops, touch cancellation/placement, failed-drop recovery and entity reuse. CI never queries the real catalog.

## The Met

Checked November 2, 2026. Keyless collection search and CC0 image import are enabled in the same source dropdown, sidebar and picker as Commons. Paintings, Sculpture, Portraits, Prints and Ceramics use the same compact icon-only topic row below the search field. These are one-click topic searches, not exhaustive department filters. Cards, appearance settings, caption editing, mouse/touch drag handling, picker selection, crop and export use the existing shared implementation.

- Uses the current `/public/collection/v1.1/search` endpoint with `offset` and a limit equal to the visible page's remaining slots (at most twelve), not the retired unpaginated search. Like Commons, collects up to twelve unique eligible images across at most five raw batches, stopping at exhaustion or the shared deadline. At most sixty object details are fetched sequentially per visible page; no unbounded catalog crawling. Pages can still contain fewer eligible images or none, with Next available when more IDs remain. Cursors advance by raw IDs consumed, not eligible-image counts, including a final partial batch at the documented 10,000-result boundary.
- Requires `isPublicDomain: true`, no nonempty `rightsAndReproduction`, both primary JPEG URLs on `images.metmuseum.org`, and a source page on `www.metmuseum.org`. Only these explicitly open-access images are labeled CC0. Creator text is stripped of markup. No rights inference from artwork age or title.
- Previews start with `primaryImageSmall` and can use a bounded temporary `primaryImage` rendition when the small image is insufficient, as described above; intentional import/drop still downloads and persists `primaryImage`. Original byte size and pixel dimensions are not supplied by this API: the shared streaming 20 MB ceiling and post-decode 40 MP ceiling still apply. Large originals can be rejected without placing anything. No TIFF, SVG or other new formats are enabled.
- One page's search/details share a 15-second deadline; originals retain the 30-second download deadline. Detail requests are spaced at least 100ms apart in the normal sequential path. Abort, stale-request guards, per-provider 429/Retry-After cooldowns and failure isolation leave Commons, Imported and the grid available. No credentials or referrers are sent.
- Shared import validates provider-bound source/image hosts, rejects embedded URL credentials and unexpected redirects, and preserves CC0/source/original/creator/entity metadata with the local blob. Entity reuse is scoped to the provider. Settings remain media/provenance-free.
- Isolated real-service check before replacement loading: the adapter's initial `painting` batch returned two eligible images out of twelve IDs, with more IDs available. A CC0 Thomas Rowlandson image downloaded directly from the deployed site origin, decoded at 3476x3100 (4.6 MB), and produced untainted PNG, JPEG and WebP canvas exports. This is a sampled Chromium compatibility check, not every record/browser or a deployed-release certification.
- Mocked desktop/mobile checks cover initial topics and their placement, debounced filtering, pagination, excluded copyright/missing image/unsafe hosts, source links, failed-import recovery, native mouse placement/entity reuse, mobile picker placement, crop, actual PNG download, local blob/provenance persistence and reload, plus stale responses, invalid/empty/quota errors and provider-name-specific messaging. Existing Commons native/touch workflows exercise the same card/drag code.

Sources: [Met API and pagination](https://metmuseum.github.io/), [Met Open Access](https://www.metmuseum.org/about-the-met/policies-and-documents/open-access), [CC0](https://creativecommons.org/publicdomain/zero/1.0/).

## Deferred Browser Candidates

Also checked November 2, 2026: Art Institute of Chicago and Cleveland Museum of Art provide keyless public-domain/CC0 metadata. Their sampled image URLs did not include `Access-Control-Allow-Origin` for `https://drexxdk.github.io`, so browser downloads/canvas exports failed even though metadata searches succeeded. Neither is exposed as supported; the experimental Chicago adapter was removed. Recheck official image delivery/CORS before considering either again. No arbitrary image proxy, gateway or backend was added.

Sources: [Chicago API/image policy](https://api.artic.edu/docs/), [Cleveland Open Access API](https://openaccess-api.clevelandart.org/).
