# Image Provider Compatibility

## Credentials Checklist

See [.env.example](../.env.example) for blank credentials and registration links for all credentialed image-provider candidates in the roadmap, plus a separate optional sign-in section. Keyless providers are listed without unnecessary credentials. Copy it to a local `.env`; real environment files are Git-ignored, while the example remains tracked.

Commons, The Met, SMK, iNaturalist and Openverse are implemented and keyless. The example's database/API/OAuth section is runtime configuration for optional accounts; other image-provider credentials remain a preparation checklist and do not enable integrations. Reserved variable names can change when those integrations are built. Credentialed image integrations still require terms/rights review and approved backend/gateway hosting. Never add a `VITE_` prefix to secrets: those variables are exposed in browser builds. Do not send secrets in chats, screenshots or commits.

## Image Rights

Integrated searches and imports accept public-domain/CC0 images only. Images requiring attribution, including CC BY, are not supported. Source metadata is still retained for review; API availability alone is not permission to reuse an image.

Legacy CC BY references remain parseable only to remove unsupported images safely. Opening a local or account grid removes these assets and clears their canvas/overflow placements, captions and crops, with a notification. Other images, captions, crops and settings are preserved. Local cleanup is autosaved; account saves exclude unsupported references, and new API writes containing them are rejected. There are no protected caption bands or credit footers; all supported image titles remain editable and can be hidden with **Show titles**.

## Metadata Caching

- TanStack Query shares an in-memory metadata cache between the sidebar and picker. Visible pages are keyed by provider, trimmed search text (bounded to the same 160 characters sent to the API), topic scope, raw starting offset, and requested page size. Both views request ten results and reuse matching page entries; Met object details are also shared. Returning to a visited page, restoring a browse topic or reopening a provider reuses fresh results. Cached data is cloned for consumers; editing a preview caption cannot alter another view's cached metadata.
- Complete results remain fresh for one hour. Inactive entries are garbage-collected after two hours; an additional 500-entry target evicts the oldest inactive metadata first, never active/in-flight work. Search pages and object details share that limit. An expired result is refreshed before being returned rather than silently treated as fresh. Search ordering can still change between independently refreshed pages; this cache is not a catalog snapshot.
- Identical concurrent queries share one request. Cancelling one consumer only removes its observer; the underlying fetch aborts when no consumers remain. Errors are not automatically retried or retained as usable results. Focus and reconnect do not trigger background refetches. Fresh cached pages remain usable during quota cooldowns or offline operation; actual network requests retain existing offline errors, Retry-After handling, deadlines and rights checks.
- Pages truncated by the shared deadline, or short pages stopped by the five-batch cap while a continuation cursor remains, carry an incomplete marker and are immediately stale; they are not treated as complete one-hour results. Reopening or requesting them again refetches within the same bounds; there is no automatic retry loop. Short pages at actual API exhaustion remain complete. Invalid Met detail schemas are also immediately stale. Valid detail metadata still passes the existing public-domain, rights and host filters before becoming an image result. This caches provider metadata, not permission guarantees or live availability; source-page review remains necessary.
- Reloading or closing the app clears this cache. It does not use IndexedDB, localStorage or service-worker runtime caching, and stores no image blobs. Local uploads retain browser-only blob persistence; imported provider images persist references and provenance, not image binaries. Reference-only account grids can reload those originals directly from approved provider hosts. Unit checks cover freshness, expiry, failure recovery, deduplication, independent cancellation, clone isolation, incomplete pages and entry bounds; mocked editor checks cover Previous/Next, repeated searches, provider reopening, sidebar/picker sharing, Met detail reuse and one-hour expiry.

## Preview Resolution

- Online cards measure their rendered width before requesting an image and respond to resizing and screen-density changes. The editor and preview selector share 128-200 CSS-pixel card limits. Resolution covers all three shapes, not just the current shape, so changing portrait/landscape/square does not need another image request. At 200 CSS pixels wide, portrait needs approximately 267 pixels of image height before accounting for screen density and the source's cover crop.
- Commons selects the smallest sufficient supported thumbnail-width bucket using original dimensions and device pixel ratio. Only validated standard Commons thumbnail URLs are resized; unknown URL layouts retain the API-provided preview. Requests never ask for a thumbnail larger than the original. Failed alternate renditions fall back to the API-provided thumbnail. The API's initial `iiurlwidth=320` supplies metadata/thumbnail URLs; it does not force the card to download that initial thumbnail before its measured rendition.
- The Met supplies only small and original image URLs, without a supported arbitrary resize contract. Cards initially use the small image and request the original if the thumbnail fails to load or cannot cover every shape at the measured size/density. Some thumbnail CDN responses omit CORS headers even when the original permits browser access. Original previews use the existing bounded 20 MB download and 40 MP decoded-image checks, temporary object URLs and cancellation/cleanup; they are not saved to IndexedDB. Failed upgrades retain a working thumbnail; when both URLs fail, the card shows an image error rather than an endless spinner. An original may be substantially larger than needed because no intermediate provider rendition is available.
- Explicit import still downloads and validates the original for the current session, not the selected preview, saving only its reference/provenance. Dropping an online image immediately marks its destination busy with a loading indicator until the original finishes downloading and decoding; failures clear the indicator, preserve the existing cell, and report an import error. Independent crops and exports up to 1800x2400 pixels per portrait card use the original resolution; images are not destructively downsampled. Reload loads the provider's original again, so provider images are not guaranteed offline. Preview sizing cannot create missing detail: undersized originals, failed renditions and provider limitations can still require upscaling. Rights and approved-host checks remain unchanged.
- Focused checks cover source orientations, card sizes and 1x/2x/3x densities, smallest sufficient buckets, desktop/mobile real decoded preview dimensions, resizing, no redundant initial thumbnail fetch, stable URLs across shapes, original-only explicit import, Met sufficient/undersized variants, failed-upgrade fallback, no persisted preview blobs and temporary-URL revocation.

## Search And Topics

- Local uploads temporarily reserve one loading card per selected file in My images, in both the sidebar and picker. Each successfully decoded image appears immediately and removes one loading card; failed files also remove their slot. Overlapping batches share the remaining-file count. These are upload feedback, not idle filler cards.
- Provider results appear progressively as validated metadata arrives: Commons can reveal its first eligible batch while replacement batches are still loading, and The Met reveals each eligible object as its details arrive. Each card keeps its own spinner until its preview loads; one slow preview does not hold back the others. Both views keep ten total slots and disable pagination until the search completes. In-flight progress is shared with concurrent consumers but never stored as a completed cached page; cancellation and stale-result guards remain independent per view. Caption edits on ready cards survive subsequent results.
- The sidebar and image picker always reserve ten online card slots. Loading and pending filter changes show a spinner in each placeholder; completed short, empty or failed searches leave the unused slots faintly visible without spinners or interactive controls. Placeholder shape and colors follow the actual cards. My images shows only saved images and the upload tile in both views, with no filler placeholders. Local upload/drop validation rejects GIF MIME types, filenames and GIF87a/GIF89a headers before storing an asset; file pickers omit GIF from their accepted types. Provider batches request the remaining slots for the actual page size, so neither view discards or skips extra results. Next is disabled on short pages, even if the bounded provider scan retains a raw continuation cursor.
- Image cards in the sidebar and picker use solid borders without an inset mask on hover or keyboard focus. Dotted hover frames and inset feedback are reserved for empty canvas cells and the upload tile; actual canvas drag-over feedback still applies to occupied targets. Source and rights actions are inside the card's hover/tap controls rather than in a footer; on touch devices, online picker cards open those controls before an explicit Use action selects the image.
- Search text and topic are independent. Typing narrows the selected topic, selecting another topic retains the text, and All removes only the topic constraint. Clearing text keeps the topic, including All. Changes reset the raw cursor and Previous history; pagination preserves both choices. With no text, a selected topic uses its provider-specific discovery query, while All searches the unrestricted eligible collection.
- Both choices survive provider switches and reloads independently in the sidebar and picker using browser-local preferences, not URL parameters. Legacy library URLs are imported into preferences and removed from the address. Cache keys and browser-history entries distinguish topics even when text and raw offsets match.
- Commons topics match fixed, case-insensitive terms in filenames and the API's category metadata, inside the existing bounded eligibility/page-filling path. These are approximate scopes, not exhaustive Commons category trees; missing or unfamiliar category names can omit relevant images, and the five-batch cap can yield short or empty pages even while raw candidates remain. No extra category-tree requests or unbounded crawling are performed. Live broad `deepcat` searches timed out, grouped `intitle:` OR clauses failed, and title-regex searches consumed approximately 15 seconds, so none of those query paths is used.
- Met uses the API's `medium` parameter for Paintings, Sculpture, Prints and Ceramics; Portraits requires a matching Portrait/Portraits detail tag and excludes records with missing tags. Medium/tag coverage is provider-defined, not an exhaustive art taxonomy. A small live `flower` check returned different totals and matching object classifications for unrestricted, Paintings and Sculpture searches. Copyright, approved hosts and size/decode checks remain unchanged.
- Focused mocked checks cover combined controls on desktop/mobile, retained text, All, clearing, topic changes from later pages, reload and picker reopening, category/tag rejection, and topic-specific cache isolation. They do not claim exhaustive topic accuracy or stable catalog counts.

## Wikimedia Commons

Public-domain and CC0 JPEG, PNG and WebP files are enabled. Other licenses, SVG, animation, unclear copyright, required attribution and nonempty additional restrictions are excluded. API access is not a warranty of rights: users must review the linked source page, especially for privacy, personality, trademark and jurisdiction-specific restrictions.

- Keyless MediaWiki Action API, anonymous `origin=*`, one provider per request. Selecting a provider in Image source loads its first browse topic automatically; compact All, Space, Nature, Art, Places and History icon buttons select its scope. The placeholder-only filter textbox automatically searches 300ms after typing stops, without a submit button. Clearing text keeps the scope, and selecting a topic immediately searches the current text within that scope. Each visible page tries to collect ten unique eligible images across at most five raw batches, requesting only its remaining slots. It stops at API exhaustion, the batch cap or the shared 15-second deadline. Smaller or empty pages remain possible; enabled Next actions preserve the raw continuation cursor without skipping eligible overflow.
- Searches include `filetype:bitmap haslicense:unrestricted` to prioritize public-domain/CC0 candidates. This hint is not trusted as permission: every result still passes license, copyright, attribution, restrictions, file and host checks. Bounded replacement batches can produce short pages even when more raw matches exist.
- Commons requests total-hit metadata alongside each search. Explicit search continuation offsets take priority. If a full raw batch returns only image-history continuation but the reported total confirms more search matches, the next offset advances by the raw batch count, including filtered records. Image-history continuation alone does not imply more search results; exhausted and short visible pages retain their existing disabled-Next behavior. Cached pages preserve the recovered offset.
- Requests omit credentials and referrers. Search text and network identity reach Commons; image requests reach its upload CDN. Local uploads are never sent. No gateway, arbitrary URL proxy, server media storage or account dependency.
- A visible page's replacement batches share a 15-second search deadline; original download timeout is 30 seconds. Deadline expiry retains fully completed batches and their continuation cursor, if any images were collected. Caller cancellation discards the search, and service/quota/malformed-response failures retain the existing error handling rather than masquerading as exhaustion. Search changes/unmount cancel and ignore stale results. HTTP 429 honors `Retry-After`, with a 60-second default. No automatic error retries. Loading, empty, offline, malformed-response, service and import failures leave Imported and the grid available.
- Initial original imports are streamed with a 20 MB ceiling, checked raster MIME and a 40 MP metadata/decode ceiling. Source URLs use approved HTTPS hosts. These are safeguards, not representative-device memory certification. Provider/entity IDs, original references, creator, license and source links persist locally and in explicitly saved account grids. Provider image binaries do not persist in IndexedDB or on the server; settings-only presets exclude provenance and media. Reimport of an already-visible entity reuses its local asset. Restored references load directly as CORS images; provider changes or unavailability can prevent rendering/export.
- Online previews and Imported use the same LibraryImage/GridCell card renderer, current shape/caption/font/color settings and hover tools. Sidebar Import actions add library-only; mouse and touch drags download/import the original into the dropped-on cell. Cancelled drags do not import or place anything, and failed drops leave the grid unchanged. Picker cards remain selection-only and intentionally import into the captured target cell. Original files use the existing independent crop and PNG/JPEG/WebP export path. Source and rights links appear inside the card controls and persist in Imported after reload; previews do not show a separate license heading or metadata-heavy card design.
- Isolated Chromium smoke check used a page with origin `https://drexxdk.github.io`, without touching the live editor. One `earth filetype:bitmap` search returned HTTP 200; an original public-domain NASA city-lights JPEG returned HTTP 200, decoded at 4800x2400 and produced untainted PNG, JPEG and WebP canvas exports. This verifies current browser CORS from that origin, not a deployed release, every catalog file or every browser.
- Browse follow-up, November 2: current Commons responses use `thumb.wikimedia.org` for thumbnails; both that host and the earlier upload host are allowed for previews, while originals remain upload-host-only. Before replacement loading, the actual adapter returned eligible first-batch examples for Space (11), Nature/Ansel Adams landscapes (12), Art (5), Places (6) and History (7). Counts and ordering can change with the catalog. All checks used isolated contexts, not the shared saved editor.
- Mocked CI checks cover desktop/mobile initial examples, compact titled topic buttons, inset search-icon geometry, contained focus feedback, debounced filtering without submit controls, topic retention on clear, current-text retention on topic changes, pagination, excluded rights, safe creator HTML-to-text conversion, stale responses, malformed data, empty/quota/offline failures, download failure/recovery, explicit import/placement, crop, actual PNG download, provenance/reference persistence and reload, plus settings exclusion. Shared-card checks compare Online and Imported across all three shapes and four caption positions with edited typography/colors, real mouse drops, touch cancellation/placement, failed-drop recovery and entity reuse. CI never queries the real catalog.

## The Met

Checked November 2, 2026. Keyless collection search and CC0 image import are enabled in the same source dropdown, sidebar and picker as Commons. All, Paintings, Sculpture, Portraits, Prints and Ceramics use the same compact icon-only topic row below the search field and combine with typed searches as described above. These scopes are not exhaustive department filters. Cards, appearance settings, caption editing, mouse/touch drag handling, picker selection, crop and export use the existing shared implementation.

- Uses the current `/public/collection/v1.1/search` endpoint with `offset` and a limit equal to the visible page's remaining slots (at most ten), not the retired unpaginated search. Like Commons, collects up to ten unique eligible images across at most five raw batches, stopping at exhaustion or the shared deadline. At most fifty object details are fetched sequentially per visible page; no unbounded catalog crawling. Pages can still contain fewer eligible images or none; Next requires a full displayed page and a continuation cursor. Cursors advance by raw IDs consumed, not eligible-image counts, including a final partial batch at the documented 10,000-result boundary.
- Requires `isPublicDomain: true`, no nonempty `rightsAndReproduction`, both primary JPEG URLs on `images.metmuseum.org`, and a source page on `www.metmuseum.org`. Only these explicitly open-access images are labeled CC0. Creator text is stripped of markup. No rights inference from artwork age or title.
- Previews start with `primaryImageSmall` and can use a bounded temporary `primaryImage` rendition when the small image is insufficient, as described above; intentional import/drop still downloads and validates `primaryImage` for the current session, saving only its reference. Original byte size and pixel dimensions are not supplied by this API: the shared streaming 20 MB ceiling and post-decode 40 MP ceiling still apply to initial import. Large originals can be rejected without placing anything. No TIFF, SVG or other new formats are enabled.
- One page's search/details share a 15-second deadline; originals retain the 30-second download deadline. Detail requests are spaced at least 100ms apart in the normal sequential path. Abort, stale-request guards, per-provider 429/Retry-After cooldowns and failure isolation leave Commons, Imported and the grid available. No credentials or referrers are sent.
- Shared import validates provider-bound source/image hosts, rejects embedded URL credentials and unexpected redirects, and preserves CC0/source/original/creator/entity metadata without persisting the provider blob. Entity reuse is scoped to the provider. Settings remain media/provenance-free.
- Isolated real-service check before replacement loading: the adapter's initial `painting` batch returned two eligible images out of twelve IDs, with more IDs available. A CC0 Thomas Rowlandson image downloaded directly from the deployed site origin, decoded at 3476x3100 (4.6 MB), and produced untainted PNG, JPEG and WebP canvas exports. This is a sampled Chromium compatibility check, not every record/browser or a deployed-release certification.
- Mocked desktop/mobile checks cover initial topics and their placement, debounced filtering, pagination, excluded copyright/missing image/unsafe hosts, source links, failed-import recovery, native mouse placement/entity reuse, mobile picker placement, crop, actual PNG download, reference/provenance persistence and reload, plus stale responses, invalid/empty/quota errors and provider-name-specific messaging. Existing Commons native/touch workflows exercise the same card/drag code.

Sources: [Met API and pagination](https://metmuseum.github.io/), [Met Open Access](https://www.metmuseum.org/about-the-met/policies-and-documents/open-access), [CC0](https://creativecommons.org/publicdomain/zero/1.0/).

## Additional Keyless Providers

- **SMK** uses the Danish national gallery's public-domain search, artwork identifiers and approved IIIF host. Imports use JPEG renditions limited to 4000 pixels on the longest edge instead of potentially huge original TIFFs. The API must explicitly mark the artwork public domain and supply its public-domain rights URL.
- **iNaturalist** searches photos with explicit photo-level CC0 licensing, not the observation's license. All, Animals, Birds and Plants combine with taxon-name searches. Only photos on its approved open-data host are imported. Searches stop at the provider's 10,000-observation boundary.
- **Openverse** searches Flickr and Wikimedia for CC0/public-domain photos only. Only their approved source/image hosts are accepted; unsafe URLs, unsupported licenses/formats and mature results are rejected. Anonymous requests have provider-controlled quotas; rate-limit errors and Retry-After remain visible rather than returning false empty results.

All three reuse the shared cache, bounded replacement-page filling, cancellation, import size/decode limits and reference-only storage. Raw cursors advance by consumed records, including filtered records, without skipping eligible overflow. Sampled browser downloads decoded successfully with CORS access; this does not guarantee every record, device or future provider response.

SMK and Openverse expose text search rather than unsupported topic filters. iNaturalist's taxonomy filters remain independent of text search, and All removes the taxon restriction.

Sources: [SMK API](https://api.smk.dk/api/v1/docs/), [iNaturalist API](https://api.inaturalist.org/v1/docs/), [Openverse API](https://api.openverse.org/v1/).

## Deferred Browser Candidates

Art Institute of Chicago and Cleveland Museum of Art provide keyless public-domain/CC0 metadata, but sampled image downloads still fail browser access/CORS checks. Neither is exposed as supported. Recheck official image delivery/CORS before considering either again. NASA is also deferred because its search records do not reliably distinguish third-party copyright restrictions. No arbitrary image proxy, gateway or backend was added.

Sources: [Chicago API/image policy](https://api.artic.edu/docs/), [Cleveland Open Access API](https://openaccess-api.clevelandart.org/).
